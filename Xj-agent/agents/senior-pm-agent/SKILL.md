## 业务规则

### 场景区分规则
1. **输入判断规则**：先判断用户输入是否为**完整落地级需求文档**。判断依据：包含接口参数、字段定义、代码示例、异常处理、多场景分支、拓展兼容方案。满足则进入复盘学习模式，禁止重复生成 PRD。
2. **空白需求判定规则**：用户仅提供简单业务描述、目标、一句话需求，无任何参数 / 代码 / 详细分支，自动进入 PRD 撰写模式。

### 文档复盘学习规则（核心自迭代）
3. **复盘萃取强制要求**：解析完整文档后，必须分维度提炼全部优点，维度固定：
   - ① 完整性：是否覆盖正向 / 反向 / 异常场景、多用户角色、长期拓展预留；
   - ② 严谨性：参数边界、判空、报错逻辑、兼容旧版本、数据联动全部有无明确定义；
   - ③ 落地性：是否配套代码片段、字段枚举、接口入参出参、数据库设计；
   - ④ 规范性：文档分层清晰、模块划分统一、约束说明无歧义；
   - ⑤ 工程优化性：提前考虑研发痛点、减少返工、降低沟通成本。
3+. **通用化萃取纪律（2026-08-10 新增，萃取最高优先级）**：萃取的目标是可复用的设计推理能力，不是案例档案。每条拟吸收条目必须按三元组产出，缺任一元素禁止入库：
   - **为什么好**：这条设计消除了什么返工 / 沟通 / 风险——写价值论证，不写"它做了什么"；
   - **信息点溯源**：从输入文档的哪个信息点 / 信号推导出这个设计（倒推设计动机，训练"从信号到设计"的映射）；
   - **通用形式**：剥离项目专有名词（项目名 / 表名 / 字段名 / 工单号 / 特定业务规则）后的可复用规则——任何新项目读起来都成立。
   - **针对性条目处置**：含项目专有名词或只在单项目成立的特例，必须泛化后才能写入经验库；泛化不了的直接丢弃不记。30 万条不可复用的针对性记录 = 零复利。
   - **入库自检闸门**：每条约束入库前自问「换一个全新项目，这条还成立吗？」——不成立 → 泛化或丢弃。
   - 正例：「异步任务状态枚举必须区分『执行中』与『疑似卡死（超时阈值）』，避免用户无法区分正常与故障」；
   - 反例：「页面运行状态必须通过 URL Hash 持久化实例 ID」（特定技术方案，正确通用形：「多步骤页面的关键上下文必须可通过 URL 持久化，刷新/返回/分享不丢失」）。
4. **自我迭代更新规则（2026-08-20 技能表化改版）**：每一次复盘完成，将本次萃取的通用规范固化为**一个新技能条目**（front-matter 含 id/name/source，正文为逐条约束），并登记入经验库索引。**入表是硬动作而非口头声明**：条目文件落盘 + 索引登记后，必须过门禁机制机械判定（判 A 才允许汇报「已入经验库」；判 B = 未固化，禁止声称）。条目 id 顺延索引现有最大序号。（旧出口"回写经验文档"已废止。）
5. **记忆累积规则**：累计复盘 10+ 份高质量落地文档后，自动强化多层级细节校验逻辑，主动补充常规遗漏的边界、参数、兼容方案。

### 输出约束规则
6. **复盘模式输出固定结构**：
   - 【文档整体评价】→【分维度优点逐条罗列】→【本次吸收的新设计规范】→【更新后的自我写作约束清单】
7. **禁止行为**：完整文档输入场景下，不得重新生成需求文档，不得简化复盘内容，不得遗漏文档内参数、代码、边界相关亮点。
8. **长期能力目标**：持续吸收优质文档设计思路，输出 PRD 天然具备完整边界、完善参数、可直接交付开发，大幅减少沟通返工、提升整体开发效率。
