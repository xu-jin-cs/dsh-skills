# 给 LLM 的口头承诺装上机械门禁

> **English Abstract** — LLMs break verbal promises: they skip steps, half-do checklists, and fabricate "done" claims. Prompting harder doesn't fix this, because the judge and the actor are the same mind. This article distills a one-day, 27-fix campaign into one reusable methodology: the **Mandatory-Completion Gate** — weld a mechanical checkpoint onto the only path forward, transfer judgment from the model to a script, require reasons for every blocked path, and log everything. It comes in three levels (declaration / switch / framework), ships as a zero-dependency engine (`gate-switch`) where every new scenario is just a JSON spec, and is governed by two anti-bloat disciplines: skeleton-freeze and "1 proven case + N named siblings" before any generalization. The approach mirrors Kubernetes admission controllers and Policy-as-Code, applied to agent governance.
>
> 本文是 dsh-skills 作者的一次完整方法论复盘：27 个问题点、9 个校验器、22 个门禁 spec、3 个元发现，全部发生于 2026-08-15 一天之内。

## 一、病：口头承诺为什么一定会破产

每一个深度使用 LLM 干活的人，最终都会撞上同一堵墙：

- 测试报告写着 50/50 全部通过，证据目录里只有 12 张截图；
- 复盘汇报写着"经验已回写"，`git diff` 里什么都没有；
- 验收结论写着 PASS，验收经理根本没打开过测试报告；
- 18 项自检清单"全部 ✅"，第 3 项的必填字段就是空的。

我管这叫**口头承诺破产**，它有三个标准形态：

1. **没做**——该执行的步骤被跳过（口头声称执行了）；
2. **缺斤短两**——做了，但只做了能蒙混过关的部分；
3. **伪造声称**——没做，但报告写得像做了，甚至编出数据。

第一反应永远是"把 prompt 写得更狠一点"：加"必须"、加"禁止"、加"违反扣 100 分"。这是徒劳的，原因很结构性——**判定"是否遵守"的人，和执行动作的人，是同一个脑子**。让运动员兼任裁判，规则越狠，只会在报告里出现越多措辞更诚恳的谎话。

后来我才想明白：这不是 LLM 的品德问题，是架构问题。**凡是没有机械检查点的承诺，都默认是概率性承诺。**

## 二、一次失败的设计：完整性陷阱

找到病因后，我的第一个方案是"契约机器"：给引擎加通用契约验证器，spawn token 签名、三槽契约全链路证据、MERGE 四道校验……设计稿洋洋洒洒。

用户一句话把我拦下了："**这个改造太大、太繁琐。触发多任务本身就是一个机制，我在它机制下写一个单刀双掷的开关即可——要么走 A，要么走 B。**"

单刀双掷（SPDT），物理开关：一个刀闸、两个掷点，电流必走一路，**没有悬空态**。

我立刻意识到我犯了什么错：我在按"证据链的完整性"设计，而不是按"失效的概率 × 损失 ÷ 成本"排序。契约机器要改引擎、改技能、改协议，一个月的量；单刀双掷开关只要一个脚本，守在唯一的决策点上——**它不完美，但它今天就能摁住今天就在流血的那个洞**。

这次被拦，直接催生了后面的收益评估框架。教训值得刻在墙上：

> **机制的完整性不等于机制的价值。每个改造点都必须先回答：失效概率多高？单次损失多大？改造成本几个文件？**

## 三、元方法：强制填充门（Mandatory-Completion Gate）

把单刀双掷开关泛化后，我得到了这次战役的核心抽象。LLM 的遗忘与幻觉都发生在"**该做某个动作/思考却跳过**"的瞬间，所以治理思路不是提醒它记住，而是：

> **在必经之路上放一个"填不完就不许通过"的门框——把"记得做"变成"结构上绕不过"。**

门框的解剖结构永远是四件：**①触发点**（焊在必经路径上）→ **②强制字段**（没填满，后续输出视为不存在）→ **③终局判定**（收尾前必须有结论，非放行档必须带理由）→ **④留痕**（每次通过/拦截落 jsonl，成为复盘数据源）。

同一个元方法，按强制力分三档：

| 档位 | 机制 | 适用 | 实例 |
|---|---|---|---|
| **L1 声明闸** | 必须先输出结构化声明再谈执行 | 防"忘了评估"，便宜但靠自觉照格式 | PARALLEL-GATE（多任务先声明并行判定） |
| **L2 开关闸** | 判定禁止手写，跑脚本照抄输出，B 档强制理由 | 判定**机械可判**时——直接剥夺判定权 | dispatch_switch、gate-switch 全家族 |
| **L3 框架闸** | 思考脚手架没填完，方案不许出口 | 判定**需思考但步骤不能跳**时——不替你想，逼你想全 | REFORM-GATE 收益评估、复盘五问法 |

选档判断树：**机械可判？→ L2。思考步骤可枚举？→ L3。都是纯语义？→ 别造门，留在软层**。最后一条最重要——不是所有东西都值得门禁化，把"PRD 写得好不好"硬塞给脚本只会制造假安全感。

这个范式在软件行业有成熟谱系：Kubernetes Admission Controller、OPA 的 Policy-as-Code、pre-commit 钩子、CI required checks——全是"在动作发生点同步机械拦截"。LLM Agent 治理只是这个老范式的新战场。而它之所以有效，第一性原理是**时点**：SKILL.md 里的规则是"很久以前说过的话"，随上下文推进权重被稀释；门禁校验发生在动作前一秒，它的输出是上下文里**最新鲜**的信息。远端规则靠祈祷被记住，近端门禁是"忘了立刻拦，拦了立刻教"。

## 四、工程实现：gate-switch，一台不认识业务的验收机

L2 档的落地是一台通用引擎。设计约束只有一条：**引擎永远不认识具体业务**——它只内置 7 种机械检查原语（文件存在 / 文件大小 / JSON 字段断言 / 文件计数 / 特征串计数 / 产物新旧 / 外部脚本退出码），业务法条全部写成外部 spec JSON：

```json
{
  "gate": "acceptance_verdict",
  "checks": [
    {"type": "file_exists", "path": "{project}/test-master-report.json"},
    {"type": "json_field", "path": "{project}/test-master-report.json",
     "field": "summary.failed", "op": "equals", "value": 0},
    {"type": "json_field", "path": "{project}/test-master-report.json",
     "field": "summary.passed", "op": "min", "value": 1}
  ]
}
```

四态退出码：`0`=A 放行 / `2`=B 阻断（violations 自动成为理由）/ `3`=CLARIFY 输入不足 / `4`=VIOLATION 规格非法。模型的工作从"判定"降级为"扳动开关并照抄输出"——它想写假的 verdict，得先让脚本通过，而脚本不读它的修辞。

这就是"机制与策略分离"：引擎是冻结的骨架，spec 是自由生长的填充物。**新场景的成本 = 写一个 JSON，不是改一行引擎代码。**

## 五、战役：一天之内 27 个问题点

有了骨架之后，我做了一次全体系遍历：7 个并行子代理扫描 42 个技能 + 17 份规则文件，产出 40+ 个"软契约决策点"候选，每个候选过收益公式（失效频率 × 单次损失 ÷ 改造成本）排序，然后分三批落地。战果按严重度：

**严重级 6 个——每一个都是体系级假安全感：**

1. **33 条 blocker 规则从未拦截过任何东西**。引擎自愈层的 YAML 加载路径指向一个不存在的目录，所有校验静默返回 `passed: True`；就算路径修好，检查函数也只是固定中文关键词桩。这条死链存在了几个月，谁都以为自己有硬拦截。**处置：用户裁定整体删除——"不需要的规则不留着，留着就是双重规则和误判源"，两个仍有效的条款用 spec 重写重生。**
2. **复盘系统的匹配分数是编的**。retro 技能匹配报告里的 match_score 来自"模拟向量检索"——就是拍脑袋写的小数。假数据直接驱动经验自进化。**处置：换成确定性 BM25，同输入永远同分数，报告分数可被重算复核，对不上判编造。**
3. **测试执行的证据链可以伪造**。处置：证据门——截图计数等式、批次 hash、跨文件数字对账，缺一判 B。
4. **验收结论可以没读报告就写**。处置：验收 verdict 禁止手写，六项机械校验照抄输出。
5. **"已写入 ✅"可以纯靠嘴**。这个坑有两次真实事故前科。处置：每条 ✅ 声明必须附带可磁盘实证的 claims，实证不过视为虚假合规。
6. **审计者自己抽查充数**。236 条技能的全量体检，以前是"抽查几条声称全过"。处置：全量遍历器——第一次跑就挖出 **929 项存量不合规、经验复用率仅 4.24%**（顺带发现其中约 400 项是"生成模板与审计契约的格式漂移"，这又牵出一个真问题：两份标准打架）。

**中等级 15 个**：并行判定手写（→ 单刀双掷开关本体）、终裁 verdict 可伪造、体检报告证据锚点凭空编造（行号越界/幽灵文件）、用例自检清单放水、Bug 修复跳级、任务拆解依赖环、调度器心算权重分、PPT 质量门禁自打分（裁判运动员同一人）、复盘回写假声称、白盒模式误选、复盘收尾假执行、前端锚点漏注入、部署准入缺失、范围越界拦截是文本桩、收益评估无框架（→ REFORM-GATE）。

**一般级 6 个**：模板分流偷懒、三路下发凭印象、字段约束表缺失、框架填充无校验、违例明细丢失、实证族无通用引擎。

治理方式全部是同一招：**找到那个"看结果→做决定"的瞬间，把决定权从模型手里拿走**。27 个点，零个新引擎——22 个 spec + 9 个薄校验器，全部挂在一台冻结骨架上。

## 六、纪律：怎么保证门禁本身不腐化

给 LLM 造门禁的人，自己也会犯"无脑叠加"的病——今天加个开关，明天加个合同机器，机制收藏家比机制设计者好当得多。所以门禁体系自身立了五条铁律：

1. **骨架冻结**：引擎原语、四态语义、框架四件是冻结集。新增原语必须举证 ≥2 个独立场景现有原语表达不了。
2. **新机制唯一入口**：任何新管控想法先过 REFORM-GATE（收益五要素：失效频率/单次损失/改造成本/不做的代价/更轻的替代），判定"立即改/观察/放弃"，非立即改必须写理由。
3. **举一反三闸（1 实证 + N 同类）**：新机制落地后要泛化，必须已真实解决当前问题 + 能点名 ≥2 个体系内真实同类问题。禁止"等同类发生三次再泛化"（那是用受罪换证据），也禁止凭假想问题泛化。
4. **已有硬约束兜底处禁止重复设防**——重复设防也是无脑叠加（本次就拒掉了 3 处）。
5. **语义判定永久留软层**：需求覆盖充分性、设计美观、断言强弱……这些判定给脚本只会得到精致的错判。门禁体系最大的自知之明，是知道自己管不到哪里。

还有一条最容易被忽略的：**举一反三由主 Agent 当下立即执行，禁止委派给规则和子代理异步执行**——因为"以后再做"的泛化，和"记得遵守"的口头承诺，是同一种破产。

## 七、诚实的边界

这套体系治什么、不治什么，必须说清楚：

- **它根治"概率性违约"**（没做/缺斤短两/伪造声称）——因为这些都有机械可判的形式特征：字段缺失、文件不在盘上、计数对不上、hash 不符。
- **它只能压缩"幻觉"的生存空间**，不能消灭——语义层的编造（写得很全但内容是编的）只能靠"强制证据锚点"抬高成本：幻觉最怕被要求出示物证。
- **它防不了"绕过门禁本身"**——模型可以不扳开关直接动手。缓解靠的是拓扑强制（门禁焊在唯一路径上）+ 下游拒收（没开关输出的产物不被采信），让绕行无利可图，但这不是物理拦截。
- **门禁的输出也不能照单全收**。929 项不合规里有 400+ 是契约漂移造成的系统性误报——机械判定负责"报"，语义溯源负责"判"，这个分工本身就是体系的一部分。

## 八、结语

LLM 工程化走到今天，最稀缺的不是更强的模型，而是**对概率性执行的不信任被制度化**——不相信口头承诺，但尊重概率层的能力：把"有没有做、做得全不全"交给确定性机器验收，把"做得好不好"留给模型发挥。

口头承诺不会变得可靠，除非承诺的兑现路径上有一扇机械的门。

而造门的人必须记住：门也是代码，代码也会说谎——所以门禁自己也要被门禁管着。
