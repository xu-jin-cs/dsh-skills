# L3 框架闸通用模板（强制填充门 · 思考级骨架，2026-08-15）

> 用途：新增任何"思考级"门禁框架时，从本模板克隆，只换填充物（字段），不动骨架。
> 骨架四件（冻结）：触发点 / 强制字段 / 终局判定 / 留痕。详见 rules/11_gate_framework.md 第四节。

```
[<NAME>-GATE] <框架中文名>
━━━━━━━━━━━━━━━━━━━━━━━━
触发点：<焊在哪个必经出口前——动作发生前/方案出口前/收尾前>

① <字段组1：问题/对象定义>（必填）
   - <子字段>：<填写要求，禁止泛泛>
② <字段组2：方案/内容>（必填）
   - <子字段>：<含自杀开关：何种情形框架直接终止并判"留软层">
③ <字段组3：评估要素>（收尾必填，缺一即方案不成立）
   - <要素1> / <要素2> / <要素3> / <不做的代价> / <更轻的替代>
④ 终局判定（三选一，非 A 档必须带理由）；**判定为设闸时，本格必须写明规范闸名 `设闸名：<语义>_gate`（命名只定身份，逻辑留待具体设计；2026-08-20 用户裁定设闸必命名）**
   - <A档：放行条件> / <B档：观察条件> / <C档：放弃条件>
━━━━━━━━━━━━━━━━━━━━━━━━
框架未填满 → 后续输出视为不存在
```

## 实例化五步法

1. 克隆本模板，命名 `<NAME>-GATE`，确定触发点（必须焊在必经路径，不能是"想起来才用"）；
2. 写填充物：三组字段 + 判定档，字段必须**可检查**（每个字段有明确文本标记词，供机械校验 grep）；
3. 配校验 spec：复制 `specs/reform_gate.json`，把 checks 里的 pattern 换成你的字段标记词；
4. 挂勾：在适用技能/规则的对应环节插入"判定禁止手写，必须经 gate_switch 照抄结论"块；
5. 登记模式库 `~/.agents/logs/pattern_registry.jsonl`（level=L3，status 按 GENERALIZE-GATE 判定）。

## 已正名实例

| 实例 | 填充物（三组字段） | 校验 spec |
|---|---|---|
| REFORM-GATE | 问题定义/方案(含问题闸决策树四节点)+机械可判性/收益五要素 → 立即改·观察·放弃 | `reform_gate.json` ✅ |
| CLARIFY-GATE | 需求五要素齐备性声明/疑问清单 → PROCEED·CLARIFY | `clarify_gate.json` ✅ |
| 复盘 5 问法 | 五个归因问题 → CLOSED 门禁 | 待填充 |
| idea-forge 11 维 | 11 个设计维度 → 出稿门禁 | 待填充 |
| 技能声明表 | 声明字段 → 打回门禁 | 待填充 |

## 边界（骨架纪律）

- L3 防"跳步"不防"瞎填"：字段存在性机械可判（本模板配套的 spec），内容正确性留软层 + 复盘审计；
- 判定若可完全机械化 → 降级为 L2 开关闸（写 gate-switch spec，不要造 L3）；
- 纯语义（无明确字段可枚举）→ 别造门，留软层；
- 骨架四件与原语冻结，扩展需 ≥2 独立场景举证。
