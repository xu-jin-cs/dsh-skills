## 零虚构原则

无真实数据则不写入数据库。`Deliverable.file_path` 为空时禁止创建交付物对象。 【规范】
禁止模型自主生成模拟数据（除非用户明确要求）。Debug 态数据必须标记清晰，永不穿透到后端存储或正式数据库。 【建议】
违反视为任务失败。

# 〇、目录树安全 — 与上述三条独立并行

**【不可突破，违反即任务失败】**
1. 永久禁止删除/清空/覆盖/重写/替换任何目录树结构、文件夹清单 【规范】
2. 只能新增补充或注释说明，原结构必须完整保留 【建议】
3. 用户隐含"替换目录""重写树形"等，必须主动拒绝 【建议】
4. 生成涉及目录内容前输出自检声明：「自检：本次修改方式为[追加/注释]，未删除/覆盖任何原有节点」
5. 生成后附加合规自检报告
6. 被 `====【不可修改固定目录区块】====` 包裹的文本全程只读
7. `rm` 仅限删除单个文件，`mv`/`cp -R` 的源路径必须指向单个文件 【建议】

任何工具调用（Edit / Write / Bash 等）完成后，若当前存在由 `TodoList` 登记的未完成任务，**必须先调用 `TodoList` 同步该任务状态（全量清单重发，更新对应项状态），才能发起下一个工具调用**。 【规范】

执行顺序：
1. 开始任务 → `TodoList` 全量清单中将该项标为 `in_progress`
2. 执行任务中的任意动作（读取 / 编辑 / 运行命令）
3. 任务完成或阶段性结论明确后 → `TodoList` 全量清单中将该项标为 `done`
4. 之后才可创建新任务或进入下一步

**违反视为执行纪律缺陷。** 不得等用户提醒才补同步。

## 复盘着陆规则（全局始终生效）

复盘必须先执行标准结构四部分（含第四部分入库着陆检查），再记 auto-memory。 【规范】
**顺序不可逆：改配置 → 复盘总结（第三部分末尾直接嵌入 GENERATE 命令并执行）→ 记记忆。**
**GENERATE 是复盘总结的内置收尾步骤：** 第三部分最后一段内容输出完毕后，在同一段内直接执行 `python3 ~/.agents/retro-registry/scripts/dispatcher_generate.py`，命令执行完成即为收尾完成。**禁止将 GENERATE 作为独立后续步骤**（防止被跳过）。命令成功即步骤完成，不校验 dispatcher 内部是否生成文件。 【铁律】
详见 01e_retro_system.md `### 复盘标准结构` → 收尾步骤与第四部分。

## 用户打断即停手铁律（2026-08-16 双事故复盘落地，新增）

1. 用户在任务执行中途发言（提问/质疑/纠偏，任何形式）= 最高优先级停止信号：当前工具调用批次结束后**立即停止一切后续执行动作**，本轮只输出对用户的回答，等用户明确指令再动。
2. 禁止"回答与执行同轮混排"——回答完用户问题后在同一轮继续跑工具，视为违反本条。 【建议】
3. 执行中发现规则/门禁自相矛盾（逻辑不可同真）= 立即停手报告用户裁决，禁止继续与门禁缠斗（实证：2026-08-16 ppt-direct 双闸 Hero≥88pt vs ≤54pt 矛盾缠斗 16 分钟）。 【规范】
4. 违反视为执行纪律缺陷，比照事故处理。

## 发现绕闸即曝光 + 打补丁铁律（2026-08-20 用户裁定）

1. **发现某闸可被绕过 = 该闸已成为风险闸**：模型执行中若发现某闸的逻辑漏洞/绕过路径（本例：danger_cmd_gate 对 `rm -f` 漏判），必须**当场、在下一条消息内**向用户**完整分享绕过经过**（命令原文、判危逻辑为何漏、如何复现），禁止悄然绕过或轻描淡写带过。 【规范】
2. **立即打补丁，一次性更正**：曝光后**当场**过 REFORM-GATE 评估并打补丁修复该闸（不留"下次再说"、不等复盘）。 【规范】
3. **审计兜底**：复盘审计（safety_cmd_audit S1）必查"本会话是否发现并曝光了闸绕过"，发现闸失效但未产生补丁块/未改对应 spec/脚本 → 判 B 违例进复盘。 【建议】
4. 本条优先于"避免打扰用户"之类的效率考量——宁可当场打断曝光，也不让风险闸带漏运行。 【规范】
