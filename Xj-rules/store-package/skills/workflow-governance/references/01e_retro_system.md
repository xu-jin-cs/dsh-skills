### 复盘标准结构

所有复盘（包括项目收尾、测试完成后、临时复盘），必须按以下四部分组织。**第四部分为强制着陆检查，与前三部分同级不可跳过。** 【规范】

（复盘挂点 `security_baseline` 与 `archmap_diff_freshness` 均已废止，见 `09_governance_archive.md` 第十节第 4、5 条。）

**第一部分：项目问题（本项目问题）**
本项目范围内发现和修复的具体问题。每项写明：
- 事故描述（用户看到了什么、发生了什么，不使用抽象标签）
- 根因
- 修复方式
- 落地方式（改什么文件）

**第二部分：对话中提出的问题（非本项目问题）**
对话过程中发现的通用问题，不限于本项目。包括：
- 流程缺陷、规则盲区
- 可复用的设计原则、治理规范
- 需要写入顶层规则或记忆的通用教训

**第三部分：执行操作问题（本来应该按照规则这么做，实际上没有这么做）**
复盘本次对话中执行层面的偏差，包括：
- 哪些步骤跳过了规则要求的流程
- 哪些方案没确认方向就动手做了
- 哪些边界校验该做没做
- 同一个模式缺陷是否跨场景重复出现

**固定扫描①（2026-08-12 新增）：执行期发现登记核对（G32 复盘侧义务）。** 读取登记池（`~/.agents/retro-registry/runtime/_retro_experiences_<project>.json`，按项目命名变体）逐条过账落地状态，并回扫本任务执行记录，确认执行过程中发现的问题全部已登记、全部纳入本次复盘。「当时已解决」不是不纳入的理由——发现过程即经验本体。漏登条目当场补登并记为复盘自身缺陷。无则写「本轮无」。
**固定扫描②（2026-08-12 新增）：决策-规则矛盾 grep。** 本次任务做出的每个关键决策，提取其关键词 grep `rules/` 与 `skills/` 全部契约文件，逐条判定命中项为保留/修订/删除；扫描结果清单化输出，矛盾未清零不得进入第四部分。

每项写明：规则要求 → 实际行为 → 根因 → 改进措施。

**→ 复盘收尾：第三部分末尾直接嵌入 GENERATE 执行（硬性，不可跳过） ←**

复盘第三部分最后一段内容输出完毕后，**紧接着在同一段内**执行以下命令（不跨步骤、不跨消息）：

```bash
python3 ~/.agents/retro-registry/scripts/dispatcher_generate.py
```

GENERATE 是复盘总结的内置收尾环节——**第三部分内容输出完毕 + 随即执行上方命令，二者构成一个连续动作，不可分割**。命令执行完成后输出 `[retro-skill-dispatcher] GENERATE 完成` 即为收尾完成，方可进入第四部分着陆检查。未执行 GENERATE 命令的复盘视为未完成，禁止进入第四部分和记忆写入。 【规范】

**执行实证（2026-08-15 裁定，gate-switch 机械门禁；注：retro_generate_token.json 依赖复盘注册表 retro-registry，未随本包发行，接入注册表后自行恢复该 spec）：** 复盘启动时先 `touch /tmp/retro_marker_<复盘名>` 标记文件；进入第四部分前必须扳动 `python3 ~/.agents/skills/gate-switch/scripts/gate_switch.py --spec ~/.agents/skills/gate-switch/specs/retro_generate_token.json --set marker=/tmp/retro_marker_<复盘名>` 照抄结论——判 A（registry-index 与角色绑定均新于标记）才允许进入着陆检查；判 B = GENERATE 未真实执行，打回第三部分末尾补跑，violations 原文即证据。 【铁律】

**会话合规审计合并闸（2026-08-19 复盘闸族瘦身，REFORM-GATE 判 A 落地；原 2026-08-17 双闸合并）：** 进入第四部分着陆检查前，除 retro_generate_token 外须扳合并闸照抄结论（证据源均为本会话 jsonl，无需参数）：
`python3 ~/.agents/skills/gate-switch/scripts/gate_switch.py --spec ~/.agents/skills/gate-switch/specs/session_compliance_audit.json` —— 一次扳动聚合三维：F 维第一推动七查（F1 扇出未扳 dispatch_switch / F2 方案未过 REFORM-GATE 裸奔 / F3 复盘未走 GENERATE 准入 / F4 掷点A未真扇出 / F6 retro-match 未运行 / F7 起手式缺失）、S 维安全三查（S1 危险命令 / S2 固定目录区块完整性 / S3 打断即停手）、T 维 todo 重发核验。判 B 则 violations 即各维违例清单：F 维记入第三部分执行偏差项，S 维按「违反即任务失败」记入第一部分。
（溯源：原 first_push_audit / safety_cmd_audit / todo_resend_audit 三闸证据源同源，2026-08-19 合并为单闸，三原 spec 保留可单独扳。）判 A 才允许进入着陆检查；判 B 未整改仍提交 → 复盘视为未完成。

**GENERATE 输出端对接闸（2026-08-17 落地，用户裁定"复盘技能对接生成器写死在输出端之前，就像当初写死 GENERATE"；注：trigger_corpus_check.json 依赖复盘注册表语料统计，未随本包发行，接入后自行恢复该 spec）：** GENERATE 执行完成后、进入第四部分着陆检查前，必须扳动 `python3 ~/.agents/skills/gate-switch/scripts/gate_switch.py --spec ~/.agents/skills/gate-switch/specs/trigger_corpus_check.json` 照抄结论——判 A（本次新入库条目的全部触发词成分均在用户历史语料中出现过，df≥1）才允许进入着陆检查；判 B = 有技能触发词未对接语料生成器（语料未见死词成分，violations 即清单），必须用生成器重生该条目触发词后复扳。每次生成必对接，不存在"这次不用"的概率空间。 【铁律】

**执行约束：**
- 命令成功执行（exit 0 且 stdout 含 `GENERATE 完成`）即为收尾完成，**不校验 GENERATE 内部是否生成文件**——dispatcher 内部逻辑由 dispatcher 自身管控
- 第三部分内容输出完成却不执行此命令直接写第四部分 → 视为 PM 失职
- GENERATE 输出到 stdout 的格式由 dispatcher_generate.py 管控，**复盘正文中只展示一行「✅ GENERATE 完成：N 条新经验入库」**，禁止在文本中转发 dispatcher 原始输出的技能明细/number ID/计数条目 【规范】

**第四部分：复盘入库着陆检查（硬性输出块，含ID编码+向量归档）**
复盘收尾（第三部分直接嵌入 GENERATE 命令并执行完成）后，输出以下内容：① 技能ID由系统分配（skill_id=retro-{role}-{NNN}，禁止手写 pXXX_YYY 序号——2026-08-12 已废除 p 系编码）；② 输出新版复盘着陆检查块(7项)；③ 展示 GENERATE 执行摘要。缺第四部分或部分着陆项未完成 → 复盘视为未完成。 【规范】

### 复盘落地门禁（硬性，不可跳过）

复盘不是只记录，每条问题必须带落地动作，否则复盘无效。 【规范】

**门禁规则：**
1. 复盘每条问题，必须标注落地方式（修改规则文件 / 修改技能文件 / 修改 AGENTS.md / 写入经验文档 / 新增 auto-memory），禁止仅记录无落地 【规范】
2. 落地方式必须是写入文件的实际操作，不能只写一行"下次注意" 【建议】
3. 复盘输出必须包含「变更文件清单」（改了哪些文件、增删行数、变更内容摘要） 【规范】
4. 缺少落地方式的复盘结论 → 视为未完成，禁止归档 【规范】
5. 复盘执行顺序严格固定：改配置 → 复盘总结（第三部分末尾直接嵌入 GENERAL 命令并执行）→ 更新 auto-memory。GENERATE 是复盘总结的内置收尾环节，非额外步骤。禁止颠倒顺序或跳过。 【规范】

### 复盘着陆检查（硬性输出块，2026-07-12 更新入库版）

> why: 本块在任何复盘输出后强制执行

复盘收尾（第三部分直接嵌入 GENERATE 命令并执行完成）后，紧接着输出以下着陆检查块。任意一项为 ❌ 则复盘视为未完成。

执行说明（①-⑧ 经 retro-skill-dispatcher GENERATE 转化完成；⑥ 为独立代码落地）：
- ① AI判断：GENERATE Step2 自动标注reuse‑flag，仅元数据备注
- ②-④：GENERATE 判定生成SKILL.md/registry/role-binding。每条复盘经验都生成对应 SKILL.md。
- ⑤⑦：GENERATE 执行审计日志+向量入库
- ⑥：涉及代码/配置/规则文件修改的，列出实际改动的文件路径和行数
- ⑧：第三部分末尾直接嵌入 `python3 ~/.agents/retro-registry/scripts/dispatcher_generate.py` 命令并执行。命令执行成功即 ✅，不校验 dispatcher 内部是否生成了文件。未嵌入执行（纯文字说明"已发起"不计数）的复盘视为未完成。
- ⑨：向量库写入必须在 registry 索引之前完成，顺序不可逆 【规范】
- ⑩：所有 retro 条目必须满足字段合规（serial_number=skill_id, business_category=佳脉, coating_tag=复盘经验） 【规范】
- ⑪：PM 在收尾前扫描本次执行记录，识别 2 次及以上重复出现的同类简单问题。能根治的必须输出具体动作（改文件/加脚本/加规则/加检查单）并执行；不能根治的说明原因并标记 ⬜ 不适用。缺少根治方案的复盘视为未完成。 【规范】
- 无合理原因标记❌ → 复盘归档拒绝
