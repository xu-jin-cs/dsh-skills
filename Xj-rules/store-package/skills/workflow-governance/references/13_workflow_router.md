## 核心总则（唯一准则，全局生效，不分流程）

**分类准入（2026-08-19 用户终裁，注册表 v1.1 起生效）：先分闸与工作流，再谈准入。**
- **工作流（entry_kind=workflow）**：**默认禁止隐式触发**，仅满足【显式注册触发词精确匹配】才可准入；不允许依靠片段关键词、语义相似、中间描述自动匹配路由；无注册触发词，一律进入通用基础链路。 【规范】
- **闸（entry_kind=gate）**：地基通路/规则级强制门禁（dual-gates、plan-select、parallel-dispatch、gate-switch、scope-boundary-gate、bug-fix-strategy、retro-skill-dispatcher），**触发词与语义命中双通道准入**——语义命中是给闸的，不给工作流。如声明闸 2 字词根白名单（"评估""查询"等）语义命中即进闸，无需用户自喊"查询闸"。

取消各工作流内部自定义匹配规则，所有路由判定收拢至顶层网关，禁止子流程自主接管会话。 【规范】

## 统一硬性约束（entry_kind=workflow 专用；闸不受以下准入限制，仅受各自闸门机制约束）

1. **准入唯一条件**：用户输入必须精确包含该工作流在全局注册表登记的触发词，缺一不可；无注册触发词直接拦截，禁止进入任何专用工作流。 【规范】
2. **禁用逻辑清单（全流程下线）**
   - ❌ 禁止局部片段关键词匹配（如"渲染卡片"匹配PPT流程） 【规范】
   - ❌ 禁止大模型语义推断、同义改写、衍生词匹配 【建议】
   - ❌ 禁止模型主动推荐、切换至专用工作流 【建议】
   - ❌ 禁止用中间过程描述词覆盖最终交付产物判定 【规范】
3. **产物兼容兜底校验（统一附加校验，不新增多层独立闸）**：命中注册触发词后，仅增加一次校验——**专用工作流输出资产必须和用户最终交付产物匹配**（注册表 output_artifact vs 用户目标产物），不匹配则拒绝进入该流程，退回通用链路。 【规范】（2026-08-20 审计 AGT-008：原 route_anomaly.jsonl 留痕条款空转清退——落地以来零记录且无读写机制，路由熔断行为保留、留痕要求删除）
4. **会话历史优先规则**：会话内存在用户验证通过的成熟执行路径时，优先复用历史路径，跳过专用工作流匹配逻辑。
5. **冲突熔断规则**：链路内规则与用户交付目标冲突时，立刻终止执行，日志告警，停止继续运算。

## 全局注册表标准结构

```json
{
  "workflow_id": "唯一流程标识",
  "entry_kind": "workflow | gate（2026-08-19 v1.1 新增：分类准入依据）",
  "registered_triggers": ["准入触发词列表（精确匹配）"],
  "output_artifact": "该流程标准产出物",
  "enable_implicit_match": false,
  "exempt_uids": []
}
```

扩展字段（本环境落地新增）：`entry_kind`（workflow=交付物流水线，仅触发词准入 / gate=地基通路闸，触发词+语义命中双通道准入，其 enable_implicit_match=true）、`routing_scope`（user_direct 用户可直接路由 / internal_only 流程内部节点不对用户路由开放 / deprecated 封存）、`note`。`internal_only` 技能由流程调度或规则级强制拉起（如 parallel-dispatch/plan-select/gate-switch/retro-skill-dispatcher 按开关第一推动触发清单扳动），例外于准入唯一条件；其中 entry_kind=gate 者允许语义命中，其余仍禁止用户语义误触发。 【规范】

## 极简路由主逻辑（无多层嵌套闸，单一流转分支）

1. 读取会话上下文，若存在已验证快路径 → 直接复用该路径执行
2. **闸通道**：输入语义命中 entry_kind=gate 条目（如声明闸 2 字词根白名单、多任务信号、需求多路径信号）→ 进入对应闸，闸按自身机制约束后续链路
3. **工作流通道**：检索全局注册表，**精确匹配 entry_kind=workflow 条目的注册触发词**
   - 未命中：路由至通用基础链路，结束路由
   - 命中：对比流程标准产出物与用户目标产物
     - 兼容：调度该专用工作流
     - 不兼容：路由至通用基础链路
4. 执行链路中出现规则与交付目标冲突 → 熔断终止，告警上报
