# Bug最短路径修复策略

## 核心原则
能改配置就不改代码，能调参数就不改逻辑，能改交互就不动业务，能改调用就不重构。

## 修复优先级（按序，不得跳级）

> **修复级别判定禁止手写（2026-08-15 裁定，gate-switch 机械门禁）：每次修复动作前扳动 `python3 ~/.agents/skills/bug_fix_gate/scripts/gate_switch.py --spec ~/.agents/skills/bug_fix_gate/scripts/specs/bug_fix_gate.json --set bug_id=<id> --set level=<N>`，判 A 才许动手；判 B 照抄理由（重复次数不足/需用户确认/跳级）。**

**第一优先：配置/参数调整**
超时/端口/路径/开关/环境变量 → 解决则止步

**第二优先：交互逻辑调整**
操作顺序/事件时机/状态判断条件 → 解决则止步

**第三优先：逻辑修改**
计算错误/业务规则/数据转换 → 解决则止步

**第四优先：方法调用调整**
参数传错/调用错误方法/返回值处理 → 解决则止步

**第五优先：重构评估（仅限重复Bug≥2次）**
≤3文件 → 直接重构
>3文件 → 向用户确认后执行

重构前必须输出方案：当前问题 / 新结构 / 改动文件清单 / 执行顺序 / 验证方式

## 禁止行为
- 禁止跳级
- 单次Bug禁止重构
- 无方案不得重构
- >3文件未确认不得执行
