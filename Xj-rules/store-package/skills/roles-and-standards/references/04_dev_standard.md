# 六、通用规则（经验积累）

> 跨项目高复用规则。项目独有经验存放在各项目级 `AGENTS.md` 中，各角色职责内经验存放在对应 skill 经验文档中。

## 一、项目管理

### 立项
- 新项目 first step：`git init` + `.gitignore`（100行代码前必须做） 【规范】
- 国内网络环境项目根目录配镜像源（`.npmrc` / pip 参数 / ghproxy）
- 配套工具放主项目 `tools/` 子目录，不独立成项目（除非有独立用户群体/发布需求/技术栈完全不同）

### 需求与设计
- PRD 必须明确目标应用类型（普通桌面/Web/客户端/游戏） 【规范】
- 布局类需求在 PRD 阶段用 ASCII 草图对齐，一次确认清楚上下左右关系+是否可拖拽
- 交互文档必须包含状态枚举章节（按钮禁用规则/颜色/标签文字） 【建议】
- 组件 UI 必须覆盖 7 种状态：默认/悬浮/选中/禁用/加载中/空状态/异常 【建议】

### 开发阶段
- 产品方向变化必须同步更新项目 AGENTS.md 【规范】
- AGENTS.md 标注所有多份副本模块，写明"修改 A 必须同步修改 B" 【规范】
- 用户说"复核/确认/沟通"时，先输理解等确认再动手，不要直接改代码
- 用户提供截图时，主动问清区域/元素名称，不靠猜测
- "支持拖拽"在现有交互路径上叠加 drag events，不改变 UI 文案样式
- 冒烟测试必须在真实目标 OS 执行，禁止代码审查替代 【规范】
- **流程/逻辑描述冲突原则：** 用户描述的执行流程与代码显示不一致时，必须先查实际代码确认真实执行顺序，再决定改哪边。不能用户说什么就改什么 — 用户可能是简化描述，代码可能已是正确版本，改显示层前必须验证。 【规范】

### 收尾与流程
- Bug 触发→输出流程状态条+启动流程B，禁止跳过诊断直接改代码 【规范】
- 任何 Bug 走完整链（记录→分析→指派→修复→验证），PM 不得自行修
- **收尾复盘第一步：PM 先发出「所有角色提交最短路径记录」指令**，等各角色提交后再做 5 问法汇总。禁止直接跳到 PM 总结。即使单角色也要声明「本次无其他角色参与」 【规范】
- 收尾/修复完成立即输出 5 问法复盘，不等用户提醒
- 复盘输出完整台账（生成了什么/改了什么/删了什么/为什么）
- **复盘前先执行模式化Bug检查清单**：setError清理/内联style计数/文件大小/死代码/新API测试覆盖/CSS变量采纳率——逐项核查，不等发现问题
- 复盘经验必须转化为配置变更（AGENTS.md/技能文件/门禁规则），不能仅写入经验文档。转化为配置的教训→下次自动生效；留在经验文档的教训→依赖人工阅读 【规范】
- **复盘经验分类门禁（硬性新增）：** 每条经验在归档前必须标注所属分类（SKILL.md流程规则/AGENTS.md硬性门禁/技能经验文档），缺少分类标注的复盘结论禁止归档。分类标准见下方「复盘层级判定与工程能力固化规则」 【规范】
- **第5层工程能力固化门禁（最高级）：** 复盘产出判断是否可工程化固化，可固化未生成 Skill/Agent → 禁止归档。详见下方「第5层工程能力固化判定标准」 【规范】
- **复盘范围扩展门禁（新增）：** 复盘5问法之前，先执行以下范围扩展自检，缺一不可：
  - [ ] 本项目的复盘结论是否完整覆盖了所有已交付功能的缺陷和踩坑？
  - [ ] 是否有跨项目/体系层面的根因（如：Hook机制设计缺陷、前端展示层Bug、流程自动化失灵）没有被纳入？
  - [ ] 用户反馈的"不满意"点是否都已在复盘中回应？是否存在用户多次提但未被纳入复盘的问题？
  - [ ] 本次问题如果在其他项目中复现，预防措施是什么？这些措施是否已写入对应角色的配置？（而非仅留在本项目经验中）
  - [ ] 复盘范围是否存在「只改服务端不改前端」「只修代码不修配置」「只改项目不改Skill」的盲区？
  - 任一项未通过 → 复盘结论禁止归档，PM必须先补齐缺失范围再进行5问法 【规范】
- **复盘后必须输出对话总结（新增）：** 复盘经验写入配置后，必须在当前对话中输出结构化总结（含：改了什么文件、改了什么配置、新增了什么规则、注册了什么retro skill）。禁止「只写文件不总结」。 【规范】
- 生成交付物前先扫描项目目录下是否存在同类历史产出物，确认格式模板后再动手。违反 Karpathy "先读后写" 规则
- 部署脚本遵守项目已有规范（macOS 用 `.command`）
- **钩子脚本禁止静默执行（2026-08-22 注记：编辑器钩子机制已于 2026-08-20 归档废止，本条钩子宫段仅作历史参考；通用原则保留——任何脚本禁止 `>/dev/null 2>&1` 静默重定向，必须保留日志输出）**。违反视为部署缺陷。 【规范】
  - **静默重定向检出判定禁止手写（2026-08-16 裁定，gate-switch 机械门禁）：** 排查/验收脚本配置时必须扳动 `python3 ~/.agents/skills/gate-switch/scripts/gate_switch.py --spec ~/.agents/skills/gate-switch/specs/zero_residual.json --set "pattern=>/dev/null" --set "path=<目标脚本glob>"` 照抄结论——判 A（`>/dev/null` 命中数==0）才合规；判 B 则 violations 原文即静默执行实证，改回日志输出后重新扳动。（zero_residual 为一模三绑参数化模板；原钩子配置文件绑定随钩子废止失效。） 【铁律】
- **单点修复必扩面审计（硬性门禁）**：任何 Bug 修复 / 代码修改完成后，自动匹配逐层审计技能并提示 PM 审阅，不等待用户提醒。PM 判定适用后再派发执行。审计范围：修完一个具体实例后，对同层所有同类入口/路径/静默失败点做逐行扫描（except/pass/return []/continue）。禁止「修 shici 就只修 shici，不审计引擎层」。审计报告产出前，Bug 不得关闭。违反视为修复不完整，PM 负监督责任。 【规范】

### 复盘层级判定与工程能力固化规则（五层体系）

复盘结论分级采用**五层判定体系**，从低到高：

| 层级 | 名称 | 说明 | 放置位置 |
|:-----|:-----|:-----|:---------|
| 第1层 | **记忆层** | 临时参考信息，跨会话提示 | auto-memory MEMORY.md |
| 第2层 | **规则层** | 可用 if/else/when 表达的流程约束 | 对应规则文件 |
| 第3层 | **SKILL层** | 标准化可调用技能 | 对应角色的 SKILL.md |
| 第4层 | **AGENTS.md层** | 全局硬性门禁 | 项目/全局 AGENTS.md |
| **第5层** | **工程能力固化层** | **可复用能力必须固化为 Skill/Agent 并形成调用闭环** | `retro-registry/` + PM 流程调用链路 | 【规范】

**核心铁律：第5层是最高优先级判定。** 所有复盘产出优先判定是否可工程化固化。可固化 → 强制入第5层，不允许降级到低层。

#### 第5层工程能力固化判定标准（无条件强制）

复盘结论满足以下任意一条，必须落地为可调用工程能力： 【规范】

- 本次解决的问题**未来会重复出现**
- 本次形成的操作步骤**可标准化、可固化、可复用**
- 本次修复的漏洞属于**流程缺失、步骤缺失、校验缺失**
- 本次优化的能力**可以交给 Agent 自动/半自动执行**
- 产出结果可以**输出固定交付物**（文档、清单、校验结果、复盘报告、检查项、流程结果）

命中任意一条 → **必须入 Skill 池 / 必须生成 Agent 能力 / 必须接入 PM 流程调用链路**。 【规范】

#### 能力落地规则：Skill vs Agent 二选一

| 方案 | 适用条件 | 产出 |
|:-----|:---------|:-----|
| **方案A：Skill** | 标准化入参+执行步骤+校验逻辑+输出结果，可被PM/Agent调用，有固定执行模板 | `~/.agents/skills/{name}/SKILL.md` |
| **方案B：Agent** | 独立职责边界+输入源+输出交付物，可与其他Agent形成上下游流转，可被PM调度 | 独立 Agent 定义 + 流程注册 |

#### 第5层闭环四件套（缺一不可）

所有第5层产出的 Skill/Agent 必须满足以下四项： 【规范】

1. **调用闭环**：触发条件、调用时机、前置依赖、后置流程、谁调用、何时调用、失败重试逻辑
2. **流程规范**：并入 PM 主研发流程链路，明确在整体流程中的位置（前置/中置/后置校验），更新对应流程节点
3. **交付物强制**：Agent 必须有固定交付物（可存档/可复盘/可追溯/可校验），Skill 必须有标准化输出结果（定义格式/字段/必填项/验收标准） 【规范】
4. **Agent 流转**（仅Agent）：上游输入来源、下游输出去向、流转触发条件、流转失败兜底、协作链路

#### 新归档终极门禁（最高级拦截）

原有三层分类门禁保留。新增第5层门禁：
**可工程化固化的能力未生成 Skill/Agent、未形成调用闭环、无交付物、无流转链路 → 直接打回，禁止归档。** 【规范】

此门禁优先级高于其他所有归档条件。第5层判定不通过 → 禁止执行三层分类 → 复盘未通过。 【规范】

### 复盘经验三层分类规则（低层归档用，第5层不受此限制）

复盘结论归档前（仅当第5层判定通过后），每条经验必须标注以下三类归属之一： 【规范】

| 分类 | 适用条件 | 放置位置 | 示例 |
|:-----|:---------|:---------|:-----|
| **SKILL.md 流程规则** | 该教训能用 if/else/when 表达为Agent执行步骤 | 对应角色的 `SKILL.md` 工作流章节 | "生成报告前先检查run-data.json" → test-executor SKILL.md 报告生成模式 |
| **AGENTS.md 硬性门禁** | 该教训是全项目/全局通用的硬性规则，跨越单一Agent | 项目或全局 `AGENTS.md` 通用规则章节 | "修复用例时禁止全量回归" → 全局 AGENTS.md §测试通用规则 | 【规范】
| **技能经验文档** | 该教训是参考性经验，不适合转化为步骤或门禁，仅作为上下文警示 | 对应角色的 `经验文档.md` | "某次因环境问题导致所有截图md5相同" → test-executor 经验文档.md |

**硬性规则：** 每条经验归档前必须声明分类 `[SKILL.md / AGENTS.md / 经验文档]`，并写明具体文件名和章节。未分类的经验视为无效复盘。 【规范】

### 技术选型：先用最轻量方案验证可行，不满足再升级
- 重方案选定前必须做可行性验证（POC） 【建议】

### 备份与目录卫生（2026-08-20 新增，REFORM-GATE 判A，Shard C 散落备份清算配套）

- **禁止源目录留 .bak/.backup 副本**：任何源目录（代码/规则/技能/配置）禁止长期留存 `.bak`/`.backup`/`.old`/`*~`/`.bak.*` 形式的副本文件，临时备份与源文件同目录混放即视为目录卫生违例 【规范】
- **临时备份当日归档或删除**：确需临时备份时，当日必须二选一处置——移入 `<项目根>/archive/backup_YYYYMMDD/<原相对路径>` 归档（先 `mkdir -p`），或直接删除；禁止过夜散落 【规范】
- **git 管理项目一律不留副本**：受 git 管理的项目，其备份副本一律删除不留档——git 历史即副本，磁盘副本是冗余且会与活文件漂移 【规范】

### 路径引用三口径与文档真源指针原则（2026-08-20 新增，REFORM-GATE v2 判A，三短板根源治理 M2/M3 配套）

根源方法论：不在损失发生后装拦截闸，在产出点消灭产生机制——正确写法必须比错误写法更省力（共享助手 1 行 vs 硬编码 0 步 vs 手搓推导 5 行，助手把阻力排序反转）；真源事实只许指针不许拷贝（拷贝数=漂移点数，复制必然脱节，与是否尽责无关）。

- **路径引用三口径（任何新代码/新配置必须遵守）**：① 仓内路径 → 引用共享助手一行得根——shell `source scripts/lib/paths.sh`（得 `PROJECT_ROOT`）、python `from backend.common.paths import PROJECT_ROOT`，均支持 env 覆盖（如 `PROJECT_ROOT` 同名环境变量）；助手不存在的项目，先建助手再写业务代码；② 用户级路径（~/.agents 等）→ env 优先 + `$HOME`/`Path.home()` 兜底（助手内置 `AGENTS_HOME` 等常量）；③ **禁止新增字面量 `/Users/*` 绝对路径**——写死即换机即死（实证：某引擎项目 85 处存量一次清算 19 文件） 【规范】
- **硬编码 tripwire（兜底非治疗）**：代码交付/收尾复盘期扳 `gate_switch.py --spec ~/.agents/skills/gate-switch/specs/no_abs_path.json --set src=<活体范围>` 判 A（活体范围字面量 `/Users/` 计数=0）；判 B 逐处按三口径改造后重扳。扫描是安全带，根治靠上一条的阻力排序反转 【规范】
- **文档真源指针原则（任何项目文档/规则文档必须遵守）**：真源在他处的事实（技能路径、架构组件清单、全局裁定），文档中只许写指针（"真源见 X"）不许拷贝内容——拷贝从写入时刻起开始漂移（实证：某引擎项目入口文档技能表/组件清单拷贝脱节一代；重写时若再拷贝即复现根源）。项目文档只保留真源就在本项目的事实（项目史、本项目红线、本项目配置）。（废止标识符 tripwire `doc_freshness.json` 已于 2026-08-20 问题闸全量复审裁定撤除：一次性迁移残渣当日已在产出点根治，一次性问题不配常设机制）【规范】

## 二、前端通用规则

- PC+手机共用 Web 模板做设备感知适配：`IS_PC = !IS_IOS && !IS_ANDROID`，按钮/标题/结果动态切换
- 图片/文件预览网格用 `repeat(auto-fill, minmax(48px, 1fr))` + 固定高度，不依赖 `aspect-ratio`（防宽屏撑高）
- 一键启动脚本：后台启动→sleep 2→`open -a "Google Chrome" $URL`，无 Chrome 则 fallback
- Vite 项目用 `<script type="module" src="/src/main.tsx">`，不要引用构建产物
- 可拖拽面板用 ref 存宽度、mousedown/mousemove/mouseup 实现，避免 setState 闭包陈旧
- **CSS变量定义时强制同步迁移组件**：定义 CSS 变量后必须在同一 PR 中搜索所有 .tsx 旧值并替换为 `var(--)`，采纳率 ≥ 80% 才能提测。禁止分两阶段（定义变量→后续迁移），第二阶段会被永久搁置 【规范】
- **try-catch 中 setError 必须清理**：catch 分支调用 `setError(msg)` 后，try 成功分支末尾必须显式 `setError('')`。轮询/定时逻辑尤需注意——error 不会自动消失。违反视为 Code Review 缺陷 【建议】
- **组件文件 ≤ 400 行**：单文件超过 400 行必须拆分子组件。内联 `style={{}}` 全项目 ≤ 50 处。新组件强制使用 CSS classes 【建议】
- **统计卡片必须可点击筛选**：任何带 stat-card 的列表面板，每个 stat-card 必须绑定 onClick 切换筛选条件（运行中/故障/基线等），不做纯展示的统计卡片。切换时须 `setPage(1)` 联动分页 【建议】
- **工具类 CSS 必须验证存在（反 Tailwind 惯性）**：本项目无 Tailwind/原子 CSS 框架，工具类全部手写于 `App.css`（如 `.flex`/`.text-nowrap`）。JSX 里写了类名 ≠ 样式生效——写 `className` 引用工具类前必须确认该类在 `App.css` 有定义；排查 UI 显示异常时禁止以「源码里写了类名」推断样式生效，必须在构建产物 CSS 中 grep 验证规则存在；缺类则补手写工具类并 `npm run build` 重新验证 dist 产物 【规范】

## 三、后端通用规则

- 代理第三方 API：遇到 CDN 差异化响应先 curl 验证，再选相近 HTTP 客户端（undici/fetch > axios）
- JSONP 接口优先用 `indexOf('({') / lastIndexOf('})')` 位置解析，不依赖 callback 名
- 调用第三方 API 前先 curl 原始接口确认响应结构
- 数据库初始化幂等（create_all 只建不删），禁止 `rm -f` 数据库文件 【建议】
- Schema 变更用 ALTER TABLE，不重建数据库
- API 代理优先 `http-proxy`，不做复杂 Header 伪造（axios/express-http-proxy 均可能被拦截）
- **PIL save() 到 BytesIO 必须显式传 format=**：`image.save(BytesIO())` 会因无可推断文件扩展名崩溃 `ValueError: unknown file extension:`，必须传 `format="PNG"/"JPEG"/"PDF"` 等。适用于任何无 `.filename` 属性的类文件对象 【建议】
- **服务上线三查（需重启生效的后端改动交付前必做）**：① `lsof -i :PORT` 核对进程启动时间 vs 代码 mtime（无 --reload 的长驻进程会跑旧代码）；② sqlite 抽查存量配置行的限流/阈值字段是否与默认值漂移（如 user_qpm=1 致全量 429）；③ 重启后连发 ≥2 次真实请求并核对 DB 落库字段（覆盖缓存命中路径）
- **进程级缓存禁止持有生命周期绑定对象**：TTL/单例缓存的值必须是原生结构（dict/dataclass/基元），禁止缓存 SQLAlchemy ORM 实例、DB 连接、文件句柄（commit 后 expire + Session 关闭 → 下一请求 detached 500）；涉及缓存的接口冒烟必须连发 2 次 【规范】
- **RAG 生成输入门禁（反幻觉）**：弱相关素材禁止进入 LLM——以查询级 BM25 词汇证据做门禁（默认 max BM25 ≥ 0.5 才放行生成），禁止用 embedding 余弦做相关性判定（中英混排模型余弦区分度不足，好坏查询无法分离）；文档数 <3 的退化分片 BM25 必出 1.0 伪命中，整路跳过 【规范】
- **存储语义迁移必须原子化执行（2026-08-12 新增）**：修改任何 DB 列的存储语义（时区/单位/编码/枚举口径）时，「改默认值 → 迁移存量 → 重启服务」三步必须连续原子完成：先停旧进程，再迁移存量，再起新进程。迁移与重启间隙内旧进程会继续按旧语义写入，产生混合数据（实证：audit_logs UTC→本地迁移间隙残留 8 行 UTC，需二次修正）。 【建议】
- **展示/时间/数值类 Bug 先确认用户观察点再排查（2026-08-12 新增）**：用户报"显示不对/时间不对/数字不对"时，第一动作是确认观察点（哪个页面/哪条记录/哪个文件/原始值还是渲染值），再开始排查；禁止凭假设逐层读源码定位（实证：audit_logs UTC 事件未先问观察点，误查技能文件/registry/LanceDB 十余轮，被用户两次打断）。 【规范】
