# problem_gate — gate-switch 实证闸

## 用途与触发

问题闸（2026-08-20 用户裁定独立成闸并亲定核心逻辑决策树）。核心逻辑：①这个问题，能不能一次性根治？→ 能：直接根治，零闸零钩，什么都不设（修 bug、删死链、改源头——一次性动作不配常设机制）→ 不能：↓ ②是不是通用问题？→ 不是（个案/一次性）：处理完即走，不设防（设了就是闸通胀）→ 是（一类问题，会复发）：才配常设机制，且预算=1 ↓ ③需要闸（拦截/判定）吗？→ 需要：最多一个闸——存在一个点全覆盖（100%）→ 设，就设在那；找不到这样的点 → 判定：此问题不是闸能解决的（设闸越多越臃肿，且不能 100% 解决）↓ ④需要钩子（时机/动作）吗？→ 需要：最多一个钩子。此时唯一剩下的设计问题只有：设在哪里。用法：提出解决方案时，问题块存为文件过本闸，四个决策节点逐一声明+终局判定（判定即设计方向）。A=四节点齐+判定明确；B=缺节点，violations 即缺失清单。节点存在性机械核验 ★命名节点：判定设闸必给 <语义>_gate、设钩子必给 <语义>_hook 命名（三闸命名规范，2026-08-20 用户裁定设闸必命名），分析质量留软层+复盘审计。与 REFORM-GATE 分工：本闸管方向过滤（设计前），REFORM-GATE 管收益取舍（出口前）。用户三次指正已内化：附身是思考维度非形态 / 载体不定死 / 不定方向。

## 扳动命令

```bash
python3 ~/.agents/skills/problem_gate/scripts/gate_switch.py --spec ~/.agents/skills/problem_gate/scripts/specs/problem_gate.json --set block=<block>
```

判定禁止手写：必须实跑上述命令并照抄输出结论，禁止凭印象声称通过/不通过。

## 退出码语义

| 退出码 | 含义 |
|--:|---|
| 0 | A：全部机械核验通过，放行 |
| 2 | B：有违例阻断，violations 即违例清单/修复指令 |
| 3 | CLARIFY：输入信号不足，先澄清再扳 |
| 4 | VIOLATION：spec 非法或前置条件缺失（按输出整改后重扳） |

留痕：`~/.agents/logs/gate_switch.jsonl`。
